# Milo V0.2 工程与验收

新增 DeepSeek 单词查询和自然网页双语翻译。原选择检测、跨 iframe 划词传递、ShadowPortal 与消息封装继续保留。翻译请求由 background 直连 DeepSeek，不再加载 Bing/offscreen 运行入口，Chrome 权限为 storage、tabs 和网页访问。

## 运行链路

划词 UI → services/translation/DeepSeekProvider → MILO_TRANSLATE_WORD → background/deepseek.ts → DeepSeek JSON 回答 → Milo 浮窗与单词存储。

网页 Command+A → content/page-translation 提取当前 DOM 的可读英文段落 → 按稳定 id 分批发送 MILO_TRANSLATE_PARAGRAPHS → DeepSeek JSON 翻译 → 在每个原英文块下用 textContent 插入中文。原段落及链接不被重写。重复快捷键移除本次所有译文；取消后的异步结果不会再改变网页。长段落会拆分请求并在同一位置合并中文。编辑器、表单、代码、隐藏内容和已有译文会跳过。

## 密钥与模型

用户在 Milo popup 的密码输入框保存自己的 API Key。密钥位于扩展本地存储 `milo_deepseek_api_key`，不会打包进代码；storage access level 限于 TRUSTED_CONTEXTS，设置写入消息只接受扩展自有页面。UI 不回显已保存密钥。模型使用 deepseek-v4-flash 的兼容名称，当前服务版本由 DeepSeek 决定。

## 2026-09-26 实测

Chrome 已加载新版，用户提供的密钥已在当前浏览器配置。真实 DeepSeek 查询 inevitable 返回“不可避免的；必然发生的”。阅读验收页按 Command+A 后，标题与两段英文下方均显示独立中文；再次 Command+A 后原页面恢复。未出现独立翻译结果看板。

自动测试覆盖 JSON 返回与段落 id 映射、缺失/重复结果拒绝、DOM 提取、原位插入与恢复、取消后的结果忽略、编辑器原生全选，以及原有保存和重复遇见链路。发布前运行 build、lint、type-check 和 test。

本版翻译当前已加载的网页正文。后续动态加载的新正文需要再次触发；PDF、图片/canvas 和跨域 iframe 正文不属于整页翻译提取范围。

## V0.2.1 扩展更新后的旧页面处理

修复扩展重新加载后旧页面的 SELECTION 异步消息产生未处理 Promise rejection 的问题。选择、空选择、Escape 和 iframe 消息均等待并处理发送结果；运行时失效时通知所有 cleanup，解除选词和键盘监听，恢复原生全选，清理旧浮窗及译文，提示用户刷新。消息封装同时处理 Chrome API 同步抛错和失效后的监听移除。回归测试模拟异步失效、runtime ID 消失、同步抛错、真实 RxJS 选择流退订和普通临时失败，保留临时失败的再次尝试能力。

Chrome 实测重新加载扩展后在旧验收页划词：出现刷新提示，错误列表未新增记录；Command+A 执行原生全选。刷新验收页后重新出现正常查词浮窗。当前 8 组、66 项测试与 build、lint、type-check 均通过。

## V0.2.2 仅翻译阅读正文

新增站点正文范围选择。X/Twitter 只读取 primaryColumn 内的 tweetText 与文章富文本正文，不包含作者账号、时间、点赞/回复等按钮和计数、预览卡片或右侧推荐。X 未识别到正文时返回空范围，不会回退到整个页面。普通网页优先 articleBody、article 和 main 正文，过滤导航、侧栏、页脚和控件。四项新增回归测试覆盖实际送给 provider 的内容仅有正文，以及周边 UI 保持原样；共 70 项测试通过。

Chrome 已更新并在真实 X 帖子页实测：8 段推文/回复正文显示中文；侧栏 Firecrawl 的英文账号介绍仍为原文，Grok/Premium 等界面标签未翻译。请求过程中已被 X 重新渲染或移除的正文节点会安全跳过。

## V0.2.3 流畅度、请求和成本

background 增加 SHA-256 查找键的持久译文缓存，按模型/提示词版本隔离；单词 30 天、段落 7 天有效，最多 500 项、约 1 MB，以 LRU 淘汰。缓存不保存原文或 URL 字段，译文中可能含应保留的英文专名。缓存与单词本分开存储，可以在设置中清除。缓存写入失败不影响已取得的译文显示。

SingleFlight 合并相同待完成查询；正文先查每段缓存，仅向 API 发未缓存的不同文本，并把结果映射回每个原始段落 id。两路网络并发，待发送的短词请求优先。每个页面有独立取消会话；取消一个读者不影响仍在使用共享结果的其他页面，最后一个读者退出时 AbortController 中止 fetch。已进入服务端的请求不能保证不计费。排队尚未发送的取消任务不会请求 API。

正文提取共享祖先可见性计算，优先处理当前可见段落；单词请求有 150 ms 稳定时间。浮窗使用 ResizeObserver 获取真实大小，浏览器缩放/窗口变化时重新定位。

请求计数回归测试验证：同时查同词只发一次请求；重复查词和后台重启后缓存命中不再请求；重复段落合并、缓存段落不会再发送；失败回答不缓存；单读者和共享读者的取消正确；排队取消不发请求。显示测试覆盖长浮窗边界、正文提取样式检查次数、隐藏祖先过滤、可见正文优先及后台取消调用。

关闭浮窗或切换词也会取消该读者的旧查询，避免快速换词后排队任务继续调用 API。Chrome 单次实测查询 inevitable：首次后台消息往返约 496 ms，重复约 1 ms，缓存中有 1 条结果。这个样例不代表所有网络延迟，且不包含界面的 150 ms 稳定等待。90 项测试、lint、type-check、build 通过。

成本按服务方实际 token 用量计，可查阅 [DeepSeek 当前价格说明](https://api-docs.deepseek.com/quick_start/pricing/)。本地结果命中没有该次模型请求；首次新内容、过期内容及未成功完成的查询仍需调用 API。不对整体省费比例或已开始请求的取消费用作保证。

## 后续优化优先级

1. 滚动新增正文按需接续：当前只处理触发时已加载的正文，X 滚动的新帖需要恢复后再触发。后续宜只翻译进入阅读区域的新正文，复用缓存并保留停止控制，避免自动处理无关内容。
2. 大词本改为 IndexedDB：当前单词本仍以整体对象读取/写入，记录多时应复用原项目 Dexie 基础设施做有索引的增量存储，需要迁移与恢复验证。
3. 原句辅助选择多义词释义：当前为可复用的单词级词义；引入原句会提高上下文准确性，也会增加输入用量及缓存键的复杂度，应单独设计。
4. 构建依赖维护：目前保留原 Node 16/React 16/Webpack 4 链路。升级应在独立变更中验证浏览器兼容与扩展加载，不与这次请求优化混在一起。
